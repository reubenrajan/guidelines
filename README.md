## What this repo does

It removes generic AI-style output and replaces it with:

- Direct, specific writing  
- Consistent structure across long-form content  
- Repeatable design patterns for readability  
- A system you can apply across docs, blogs, and evaluation frameworks  

Two files drive everything.

---

## The system

### Writing rules → [spec-writing.md](./spec-writing.md)

A strict operating guide for how text should read.

- Lead with specifics — names, numbers, facts  
- Cut vague or inflated language  
- Avoid clichés and AI phrasing  
- Use plain words, not corporate jargon  
- Vary sentence rhythm, avoid template patterns  

Use this when writing, editing, or reviewing content.

---

### Editorial system → [spec-editorial.md](./spec-editorial.md)

A reusable structure for presenting content.

- Typography: serif display + sans body + mono for data  
- Layout: single-column editorial rhythm, strong section breaks  
- Components: grids, comparison tables, callouts, scoring blocks  
- Color: one accent (purple) + controlled use of signal colors  
- Interaction: minimal, restrained, functional  

Use this when building documentation, reports, or content sites.

---

## Example workflow

1. Draft using `spec-writing.md` rules  
2. Remove banned words and weak phrasing  
3. Add concrete examples and numbers  
4. Structure into sections using editorial components  
5. Apply layout patterns from `spec-editorial.md`  
6. Validate using the checklist  

## What this avoids

- “In today’s fast-paced world…”  
- “This plays a crucial role…”  
- “Let’s explore…”  
- Generic summaries and restatements  
- Over-designed, card-heavy layouts
